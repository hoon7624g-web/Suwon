# 다른 도시로 옮기는 안내서 — 군산 → 대구(또는 다른 도시)

> 2026-10-10 작성. 군산 사이트(https://gunsan.webforai.kr)를 만든 세션의 기록을 바탕으로, 같은 방식의 새 도시 사이트를 **새 저장소·새 세션**에서 시작할 때 읽는 문서다.
> 새 세션에서는 이 문서를 먼저 읽고, 0단계의 결정이 끝난 뒤 1단계부터 진행한다.

## 3. 작업 순서 (군산에서 실제로 걸린 순서를 다듬은 것)

1. **연결 진단**: `TOURAPI_KEY`를 `.env`나 환경 변수에 두고(커밋 금지, `.env`를 열어 보지 않는다) `python tools/tourapi_doctor.py`
2. **목록 수집**: `tourapi_bulk.py`로 지역 목록·좌표·사진(공공누리 제1·3유형만). 광역시 처리부터 고친다(2절 첫 줄)
3. **상세 수집**: `tourapi_details.py`(detailCommon2·detailIntro2)로 전화·이용시간·쉬는 날·요금·주차·체크인. 필드마다 출처와 확인일을 남긴다
4. **시 공식 자료**: 대구 관광 사이트, 공공데이터포털 표준데이터(전국주차장정보표준데이터, 버스정류장), 시 지정 음식점 목록. 두 출처 값이 다르면 둘 다 보여 주고 '방문 전 전화 확인'
5. **장소 요약**: 상투구 금지, 그 장소만의 사실 1개 이상. 쓸 사실이 없으면 짧게 두고 색인에서 뺀다(색인 기준 = 유형별 필수 정보 2개 + 요약 규칙 + 검수일 또는 운영자 공개 승인)
6. **가이드**: 실제 질문 하나에 답하는 형태로(예: '월요일에 여는 맛집', '늦게까지 하는 식당', '관광지 근처 공영주차장', '시내버스 번호'). 군산에서 AI가 "공식 자료에도 없다"고 답한 질문을 우리 가이드가 채운 경우가 가장 강했다
7. **코스·행사·영상**: 시 공식 코스, TourAPI 행사, YouTube(oEmbed로 확인)
8. **디자인**: 엔진 그대로. 홈 첫 화면 사진과 이야기만 대구 것으로
9. **공개 준비**: `build_public.py`(빌드·검증·IndexNow 키) → 서치콘솔 3곳 → GA4·GTM → `approve_publication.py`로 운영자 공개 승인
10. **측정 질문표**: N(자연 발견)·L(롱테일)·S(사이트 추천)군을 대구 데이터로. 질문마다 답이 있는 우리 페이지(`answer_urls`)를 적는다

## 4. 새 CLAUDE.md에 그대로 옮길 규칙

군산 `CLAUDE.md` 3절·4절·7절의 원칙은 도시와 무관하다. 아래는 꼭 옮긴다.
- 사실은 출처 데이터에서만. 없는 값은 '확인 필요: 요금·주차'처럼 한 번만. 추정으로 채우지 않는다
- 필드별 출처·확인일. 두 출처가 다르면 둘 다 보여 준다
- 시 원문은 링크로만, 우리 문장으로(15자 이상 연속 일치 금지). 표의 값은 그대로 써도 된다
- TourAPI 이미지는 제1·3유형만, '출처: 한국관광공사'. 제3유형은 자르기·확대·보정 금지. overview 문장은 게재하지 않는다
- 제3자 콘텐츠(네이버 플레이스·블로그·리뷰·평점) 복제 금지, 근거 없는 업체 추천 금지
- 공개 범위·도메인·GA4·브랜드·공개 승인은 사람이 정한다
- 첫 화면을 스크립트로 숨기지 않는다. 모바일 LCP ≤ 2.5초, CLS ≤ 0.1, 첫 방문 글꼴 ≤ 300KB
- 화면에 확인일을 표시하지 않는다(군산 운영자 결정 2026-10-09). 구조화 데이터의 날짜는 남긴다

## 5. 이번에 배운 것 — 같은 실수를 하지 않으려면

1. **도메인은 첫날 정한다.** 군산은 공개 이틀 동안 주소를 한 번 옮겼고 한 번 더 옮길 예정이다. 옮길 때마다 308 규칙, 서치콘솔, IndexNow, 측정 질문표 주소를 다시 해야 했다. 308 규칙은 IndexNow 키 파일(`<key>.txt`)을 빼고 걸어야 옛 주소로도 제출된다.
2. **색인은 생각보다 느리다.** 공개 3일차(10월 10일)에 Bing `site:` 검색 0건이었다. Bing 웹마스터의 '발견된 URL 779'는 사이트맵을 읽었다는 뜻이지 색인됐다는 뜻이 아니다. ChatGPT 검색은 Bing에 많이 기대므로 그 전에는 질문해도 우리 사이트가 안 나온다. 첫날 서치콘솔 3곳 등록·사이트맵 제출·IndexNow를 하고, 이미 검색에 잡히는 곳(회사 글·보도자료)에서 링크를 거는 게 빠르다. 구글 서치콘솔에는 10월 9~10일에 이미 크롤링 기록이 생겼다.
3. **AI 인용 시험은 깨끗한 환경에서.** 로그인한 본인 ChatGPT는 이전 대화 기억 때문에 우리 사이트를 1위로 추천했지만, 다른 사람 화면에는 안 나왔다. 로그아웃 상태나 임시 채팅에서 시험한다.
4. **한글 주소와 ChatGPT.** 한글을 그대로 붙인 주소는 못 열고, 인코딩한 주소(`%EA%B5...`)와 영문 주소는 열었다. 보고·영업 자료에는 인코딩한 주소를 쓴다. 다른 AI는 한글 주소 페이지도 읽었다.
5. **영어판은 코드가 따로다.** 구조화 데이터를 고칠 때 `jsonld.py`만 고치고 `en_site.py`를 빠뜨려 영어 페이지에 사진 정보 두 항목이 빠진 채 배포된 적이 있다. 한·영 둘 다 고치고 둘 다 테스트한다.
6. **서치콘솔 이미지 메타데이터.** 사진 구조화 데이터에 `creator`·`acquireLicensePage`가 없으면 알림이 온다. 지금 코드에는 들어 있다(`jsonld.image_objects`, `en_site`).
7. **제3유형 사진은 무겁다.** 원본이 0.4~0.7MB인데 다시 인코딩할 수 없어 모바일 LCP가 8초까지 나왔다. 장소 첫 화면에서 제3유형 사진은 1024px 이상에서만 보이고, 모바일은 이름 띠만 보인다(`47-place-hero.css`).
8. **한 글자가 신뢰를 깎는다.** '프리미엄'이 '프리'로 잘려 나간 것을 운영자가 찾았다. 공개 전에 전체 표기 점검을 한 번 돌린다.
9. **배포 명령은 미리 허락을 받는다.** 자동 모드에서 공개 승인(`approve_publication --apply`)·배포가 '운영 배포'로 막힌 적이 있다. 사람이 명시적으로 허락하면 진행된다.
10. **다중 에이전트 작업은 토큰을 많이 쓴다.** 군산에서는 대량 수집·대규모 리디자인 같은 큰 단계에만 쓰고, 나머지는 한 에이전트로 처리했다(운영자 요청).
